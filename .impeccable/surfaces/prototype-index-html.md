# Keylane 首个界面：快捷入口

## 设计依据

- 产品机制：在可信的固定站点配置中，选择站点后打开页面并按该站点规则填充、提交。
- 用户现场：个人在浏览器中频繁进入少量内网系统；最常见任务是找到站点并点击“进入”。
- 首屏任务：让站点名称、域名、凭据方式和下一步动作可以快速扫读；权限缺失必须有不同的动作。
- 范围：Popup、Side Panel 和扩展内管理页的交互原型。仅模拟状态，不访问站点或保存数据。

## QUALITY BAR

在 420px Popup 首屏，用户不用进入详情就能辨认当前匹配页、常用站点、各站点凭据方式以及“进入／授权”动作。五条样例应有一致行高、清楚的数字索引、无横向溢出。点击“进入”只能报告填充或提交动作，不得暗示服务器认证成功。Side Panel 保持同一信息顺序；管理页再展开登录规则与迁移。

## 页面分工与关键状态

1. Popup：搜索、当前页面匹配、常用站点和明确的一键动作；底部进入完整列表与配置。
2. Side Panel：沿用紧凑操作清单，供浏览时持续访问。
3. 管理页：左侧导航、中部站点索引、右侧规则检查器；凭据来源和登录动作分开配置。
4. 权限缺失：行内展示“授权”；授权后可再次试用。自定义脚本导入后需逐站审阅并启用。
5. 导入导出：先解释明文密码和脚本范围，再预览与确认；原型只用虚构数据模拟。

## 原型与实现边界

参考稿是方向图。实际 Popup 以浏览器扩展的窄面板密度为准，原型外层的深色标题栏只是评审切换器，不属于扩展 UI。`prototype/` 不含 Manifest、Chrome API、真实凭据持久化或真实登录。后续实现须遵循 `docs/PRODUCT.md` 与 `docs/TECHNICAL.md` 的权限、URL 匹配和执行契约。
